## Findings

### P0 — Room messages are hidden after 72 hours, not deleted

The UI says messages expire from view after 72 hours. The database policy also
filters out older rows, but the rows remain in `chat_messages`. That is an
important privacy distinction for this app.

Fix: add a SQL cleanup function and Supabase Cron job to hard-delete old
messages and reports in small batches. Supabase documents Cron as `pg_cron`
inside Postgres, and recommends scheduled hard deletes for old soft-deleted data:
https://supabase.com/modules/cron and
https://supabase.com/docs/guides/database/postgres/data-deletion.

### P0 — Room has no server-side rate limit or moderation rail

The 7-second limit lives in the browser. Anyone can bypass it by calling
Supabase directly with the public anon key. RLS protects room access, but the
write path should enforce per-user pacing in SQL.

Fix: move message insert behind a `gal_send_message` RPC that checks membership,
message length, no links, chat enabled, and last message time before insert.
Keep the client throttle for feel, but make the database the source of truth.

### P0 — One public room code is easy to abuse

`SISTER` is simple and memorable, which is good for testing, but bad as the only
production room. A public default room with no facilitator is the main safety
risk in the app.

Fix: keep `SISTER` for demo/testing, then add invite-only room codes for real
groups. Disable public room creation. Add an admin-only room kill switch and a
clear user-visible "room closed" state.

### P1 — Support and clinic data are still the launch bottleneck

Current counts:

- Articles: 34 total, 8 empty bodies, 0 human-verified.
- Support resources: 12 candidates, 0 verified.
- Referrals: 14 candidates, 11 with published URLs, 0 verified phone lines.
- Clinics: 0.

The gates are correct. The missing work is verification and sourced writing.

Fix: create a verification sprint list with the first 10 calls: Sauti 116,
MIFUMI, police emergency, Butabika, Mental Health Uganda, Uganda Law Society,
Justice Centres Uganda, one public hospital, one private hospital, one post-rape
care point.

### P1 — Some stored numbers conflict with current public sources

Examples checked today:

- Uganda Police publishes `999/112` and `0800199399` on its emergency numbers
  page: https://upf.go.ug/national-emergence-toll-free-numbers-for-public-safety/.
- MGLSD publishes Sauti 116 as toll-free, countrywide, and 24/7:
  https://mglsd.go.ug/uganda-child-helpline-116-2/.
- MIFUMI publishes `0800 200 250`:
  https://mifumi.org/.
- Butabika publishes `0800 211 306` and a direct line:
  https://www.butabikahospital.go.ug/.
- Uganda Law Society's current contact page appears to publish `0800 355 355`,
  not the variants already recorded in `content/support.ts`:
  https://uls.or.ug/contact-us/.
- Find a Helpline lists Mental Health Uganda as `0800 21 21 21`, Mon-Fri
  8:30am-5pm: https://findahelpline.com/organizations/mental-health-uganda-toll-free.

Fix: update candidate records only when the source is primary or explicitly
helpline-verified, then phone before setting `verified: true`.

### P1 — The three empty violence-response articles should be written first

The empty articles with the highest user value are:

- `it-happened-last-night`
- `he-beat-you`
- `going-to-the-police`

Useful current sources:

- Uganda Police public forms include Police Form 3 and Form 3A:
  https://upf.go.ug/police-public-forms/.
- GOV.UK's Uganda rape/sexual assault guidance was updated 2025-01-14 and
  includes police process, Form 3A, medical examination, PEP, and emergency
  contraception timing:
  https://www.gov.uk/government/publications/uganda-information-for-survivors-of-rape-and-sexual-assault/uganda-information-for-victims-of-rape-and-sexual-assault.

Fix: write these as practical, non-legal guidance with explicit source notes in
comments. Keep the same tone as existing GAL articles.

### P2 — Deploy documentation was stale

`README.md` and `docs/deploy.md` still described the pre-room version: no
database, no env vars, nothing leaving the device. That is now fixed in the
working tree.

### P2 — Dependency audit still flags Next/PostCSS

`npm audit --omit=dev` reports 2 high-severity dependency findings through
Next/PostCSS. The automated fix wants `next@16.3.3`, which is a breaking upgrade
from the current Next 14 app.

Fix: do not force-upgrade during feature work. Plan a separate Next 16 migration
with route/build testing, or wait for a non-breaking patched Next 14 release.

### P2 — Service worker cache needs a bump before deployment

`public/sw.js` uses `CACHE = "gal-v19"`. Any deploy that changes app behavior
should bump this so installed users do not keep the old shell.

Fix: bump the cache string as part of the deploy commit.
